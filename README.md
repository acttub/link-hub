# link.acttub.com

인스타그램 프로필 바이오에 거는 **링크 허브** 한 장짜리 정적 페이지.

배포: <https://link.acttub.com> (Vercel 프로젝트 `link-hub`)

## 왜 있나

인스타 바이오는 링크 슬롯이 하나뿐인데, 게시물마다 목적지가 다르다.
인스타 기본 다중 링크 기능은 제목 30자만 보이는 선택 시트를 띄워서
클릭이 한 번 더 늘고, 어느 게시물에서 왔는지와 무관하게 같은 목록이 나온다.

그래서 바이오 링크는 이 페이지 하나로 두고, 여기서 목적지를 나눈다.

**단, 광고·스토리 링크는 이 페이지를 거치지 않는다.**
의도가 이미 정해진 트래픽이므로 각 사이트로 직행시킨다.
허브는 "어디서 왔는지 모르는" 프로필 방문자만 받는다.

## 구조 — 계층이 핵심

평평한 Linktree식 나열이 아니다. voice·acti는 acttub과 경쟁하는
형제 서비스가 아니라 코어로 태우려고 만든 유입 경로이므로,
같은 크기로 나열하면 깔때기가 옆으로 눕는다.

페이지는 네 덩어리다 (2026-07-26 개편).

1. **정체** — 마스코트 + `acttub` + 한 줄. 인스타에서 처음 넘어온 사람이 여기가 뭐 하는 곳인지부터 만난다.
2. **acttub** — 큰 메인 카드. 시선이 먼저 간다. **"무엇을 하는 서비스인가"를 이 카드 안에서 3단계로 설명한다** (올린다 → 질문을 주고받는다 → 내 문장으로 남는다).
   설명을 카드 위로 빼지 않은 이유: CTA가 접힘 아래로 밀려 지금 되는 전환을 깎는다. 그래서 랜딩 역할을 카드가 흡수한다.
3. **가볍게 해보기** — 보이스 컬러(30초) · 내 연기 캐릭터 찾기(2~3분). 작은 행. **서브프로젝트가 늘어나면 여기에 붙인다.**
4. **푸터** — 인스타 계정.

> ⚠️ **3번은 최대 4개까지만 노출한다.** 행이 많아지면 작은 행들의 총 무게가 메인 카드를 눌러
> 깔때기가 옆으로 눕는다. 5번째가 생기면 추가가 아니라 **교체**다 —
> 무엇을 뺄지는 목적지 referrer 숫자로 정한다(아래 "측정").

**왜 마스코트인가**: 로고(파란 A)를 64px 정사각형으로 얹은 옛 헤더가 템플릿처럼 보였다.
마스코트는 브랜드 폴더의 마스코트 문서가 "서비스 소개·시작 화면"에 허용한 자리다.
아바타용으로 지정된 **상반신 에셋**을 쓰고 받침 원은 코드로 그린다(전신 배경 원이라 테두리는 두지 않는다).

**로고는 빼지 않았다.** 마스코트는 허용된 장식이지 브랜드 식별자가 아니라서,
파란 A를 24px로 이름 옆에 남긴다. **단 공유 이미지(`og.jpg`)에는 마스코트를 넣지 않는다** —
마스코트 문서의 금지 항목이다.

**범주를 먼저 밝힌다**: 인스타에서 막 넘어온 사람은 이름만 보고 무엇인지 모른다.
그래서 이름 아래 첫 줄이 `질문 기반 AI 연기 연습 파트너`다(볼트 지침의 한 줄 정의 그대로).
그 다음 줄이 태도(`답을 주는 대신, 같이 질문합니다`)다.

## 파일

```
index.html      허브 페이지 전부 (Tailwind CSS, styles.css를 링크)
styles.css       Tailwind CLI가 src/input.css에서 구운 결과 (커밋함, Vercel이 그대로 서빙)
src/input.css   Tailwind 진입점 — @theme 토큰 · .item 컴포넌트 · .rise 모션 · @font-face
go.html         채널 유입 기록용 경유 페이지 (아래 "채널별 유입 기록")
apps-script.gs  go.html이 보낸 기록을 구글 시트에 쌓는 수신 코드
vercel.json     cleanUrls + 빌드·설치 비활성(정적 서빙 유지)
mascot.webp     헤더 마스코트. 브랜드 폴더의 "상반신-투명"을 256px webp로 구운 것(9KB)
logo.png        브랜드 폴더의 로고를 180px로 축소한 것. 헤더에서 24px로 쓴다
```

스타일은 Tailwind로 짠다. `index.html`의 클래스를 고쳤으면 `npm run css`로 `styles.css`를
다시 구워 커밋한다. Vercel은 빌드하지 않고 커밋된 `styles.css`를 그대로 서빙한다.

```bash
npm install   # 처음 한 번 (node_modules는 커밋하지 않음)
npm run css   # src/input.css → styles.css
```

> 외부 스타일시트라 `index.html`을 파일로 그냥 열면(file://) 스타일이 안 붙는다.
> 화면을 확인하려면 정적 서버로 연다: `npx serve` 또는 `python3 -m http.server`.

## 채널별 유입 기록 (`/go`)

`acttub.com`은 소스 저장소가 특정되지 않아 우리가 계측을 붙일 수 없다.
그래서 "필름메이커스 글을 보고 왔다"를 남기려면 **우리가 소유한 이 도메인을 한 번 거쳐야** 한다.

```
https://link.acttub.com/go?from=filmmakers
        → from 기록 → https://acttub.com/?from=filmmakers 로 자동 이동
```

- 사람에게는 거의 직행처럼 보인다(화면이 뜨기 전에 넘어간다).
- 시트에 남는 것: 도착 시각 · 채널(`from`) · 전체 링크 파라미터 · **출처 사이트**(도메인까지만) · 클릭 ID.
  - 직전 페이지의 전체 주소는 일부러 버린다 — 보내는 쪽 설정에 따라 검색어·계정 ID가 딸려올 수 있다.
  - 클릭 ID는 클릭 1건마다 새로 만든다. **같은 사람의 재방문을 잇지 않는다** —
    그러려면 브라우저에 식별자를 남겨야 하는데 채널을 세는 데는 필요 없다.
- 원래 쿼리는 목적지까지 그대로 넘긴다 — 나중에 `acttub.com`에 계측이 붙으면 거기서도 보인다.
- 뒤로가기를 누르면 원래 보던 글로 돌아간다(`location.replace`라 경유 페이지가 기록에 안 남는다).

### 켜는 법

`go.html`의 `ENDPOINT`가 **비어 있으면 기록만 안 되고 이동은 정상 동작한다.**
채우는 순서는 `apps-script.gs` 맨 위에 있다.

⚠️ **리뷰 폼과 시트·배포 URL을 절대 공유하지 않는다.** 이 저장소는 공개라 여기 적힌
주소는 누구나 볼 수 있고, 그건 곧 누구나 POST를 보낼 수 있다는 뜻이다. 이 시트는 가짜 행이
쌓이는 정도가 최악이라 감수하지만, 전화번호가 들어 있는 검증 응답 시트에는 같은 문을 열면 안 된다.

새 채널을 추가할 때 코드는 건드리지 않는다. `?from=` 값만 바꿔 링크를 만들면 된다.

## 인스타 인앱 브라우저 빠져나오기 (2026-07-28)

바이오 링크를 누르면 인스타 안에 갇힌 웹뷰로 열린다. 여기서 진짜 브라우저로 빼내는 건
**안드로이드만 된다.** 코드는 `index.html` 맨 위 인라인 스크립트 + 그 아래 배너 두 줄이 전부다.

| | 보이는 것 | 동작 |
|---|---|---|
| 안드로이드 인앱 | **`브라우저에서 열기` 버튼** | 열자마자 `intent://`로 자동 전환 시도 + 버튼으로 확실한 길 |
| iOS 인앱 | **`··· 메뉴에서…` 문구** | 자동 전환 불가, 사용자가 직접 |
| 그 외 브라우저 | 아무것도 안 보임 | 아무 일도 없음 |

**iOS가 안 되는 건 브라우저 종류 문제가 아니다.** 크롬이라서 막힌 게 아니라 WKWebView가
어떤 커스텀 스킴도 호스트 앱에 넘기지 않아서다 — 사파리·웨일·파이어폭스·삼성인터넷 전부 같다.
예전에 쓰던 `x-safari-https://`도 인스타가 막았다. iOS에서 특정 브라우저를 지정할 방법은 없다.

**안드로이드에서 크롬을 `package`로 못박지 않는다.** 못박으면 크롬이 없는 기기에서 실패하고,
그때 쓰는 `S.browser_fallback_url`은 안드로이드 시스템이 아니라 **intent를 해석한 쪽**이
처리하는 관례라 인스타 웹뷰가 구현하지 않았으면 에러 화면으로 끝난다. `package`를 빼면
기본 브라우저는 항상 존재하므로 그 실패 경로가 사라진다. 기본 브라우저가 크롬인 기기가
대부분이라 실제로도 크롬이 뜬다.

**자동 전환은 보장되지 않는다 — 그래서 버튼이 있다.** 파싱 중 실행되는 `location.replace`에는
사용자 제스처가 없어서 브라우저·웹뷰가 intent 실행을 거부할 수 있다. 자동은 "되면 좋은 것"이고,
탭에는 제스처가 붙으므로 **버튼이 확실한 길**이다. 둘 다 같은 주소를 쓴다.

**버튼의 `href`는 요소 바로 뒤의 인라인 스크립트가 채운다.** 목적지가 현재 주소에 따라 달라져
마크업에 못 박을 수 없어서다. 두 가지를 일부러 피했다:
- `DOMContentLoaded`를 기다리는 방식 — 버튼은 파서가 지나가는 즉시 보이는데, 그 사이에 누르면
  자리표시자로 이동해 UTM이 날아간다.
- 클릭을 리스너로 가로채는 방식 — 가운데 클릭(`auxclick`)과 길게 눌러 "새 탭에서 열기"를 놓치고,
  `Element.closest`가 없는 구형 웹뷰에서도 새어나간다.

네이티브 링크 동작에 맡기는 게 빈틈이 없다. 자리표시자를 `href=""`로 둔 것도 같은 이유다 —
혹시 그 값이 쓰이더라도 현재 주소 그대로라 UTM이 남는다.

- **`?ib=1`은 자동 전환만 끄는 스위치다.** 버튼은 그대로 남는다. 손으로 확인할 때 쓴다:
  `https://link.acttub.com/?ib=1`. 판정은 문자열이 아니라 `URLSearchParams`로 해서
  `?ib=%31` 처럼 인코딩돼 들어와도 같게 읽는다.
- **UTM은 그대로 넘어간다.** 브라우저에서 다시 여는 주소는 원래 주소와 같다.
- **`navigator.webdriver`가 서 있으면 자동 전환하지 않는다.** `tools/device-matrix.py`의
  `insta-inapp-android` 프리셋이 인스타 UA로 도는데, 거기서 페이지를 떠나버리면 하네스가
  잴 대상을 잃고 크래시한다. 배너는 그대로 켜지므로 인앱 화면 검사는 유지된다.
  실제 사용자 브라우저에서는 이 값이 서지 않는다.
- ⚠️ **버튼 마크업에 `flex` 유틸리티를 넣지 않는다.** 유틸리티 레이어가 컴포넌트 레이어를 이겨
  `display:none`을 덮어버리고, 일반 브라우저에서도 버튼이 보인다. display는 `src/input.css`가 쥔다.
- **조회수가 두 번 잡힐 수 있다.** 인앱에서 한 번, 브라우저에서 한 번. 전환 스크립트를
  계측 스크립트보다 위에 둔 건 이걸 줄이려는 것이고, 완전히 없애지는 못한다.
  안드로이드 유입 비중만큼 허브 조회수가 부풀 수 있으니 CTR을 볼 때 감안한다.
- **배너 문구는 메뉴 위치를 단정하지 않는다.** `···` 위치와 항목 이름이 OS·앱 버전마다 달라서,
  "오른쪽 아래"라고 썼다가 거기 없으면 안 쓰느니만 못하다.
- ⚠️ **되돌리려면 스크립트 블록과 배너 두 줄만 지우면 된다.** 나머지는 건드리지 않았다.
- ⚠️ **실기기 확인이 남아 있다.** 인스타 안드로이드 웹뷰가 `intent://`를 넘겨주는지는
  이 저장소에서 실측한 적이 없다. 안드로이드 폰의 인스타에서 바이오 링크를 눌러
  ① 자동으로 브라우저가 뜨는지 ② 안 뜨면 버튼이 되는지를 확인한다.
  둘 다 안 되면 스크립트만 지우고 버튼은 남겨도 된다.

## 유의사항

- **`target="_blank"` 금지.** 인스타 인앱 브라우저에서 새 탭이 안 열리거나
  웹뷰가 겹쳐 사용자가 돌아갈 길을 잃는다. 전부 같은 탭 이동.
- **링크에 UTM 유지.** `utm_source=linkhub&utm_medium=bio&utm_campaign=hub`.
  허브에서 셋 중 어디로 갈리는지 이걸로 측정한다.
- **문구는 제품 가드레일 적용 대상.** 점수·등급·평가·처방 프레임 금지.
  볼트 `AGENTS.md`의 "제품 가드레일" 절이 정본. 문구 고치면 다시 검사할 것.
- 로고는 볼트의 브랜드 폴더가 정본. 바꿀 일이 있으면 거기서 가져와 축소한다.

## 배포

`main`에 push하면 Vercel이 자동으로 프로덕션(`link.acttub.com`)에 반영한다.
로컬에서 `vercel --prod`를 치지 않는다.

```bash
git push origin main
```

다른 브랜치로 push하면 미리보기 URL만 생기고 프로덕션은 그대로다.

DNS는 Cloudflare에 CNAME `link` → Vercel, **proxy는 반드시 DNS only(회색 구름)**.
주황 구름이면 인증서 발급이 막힌다.
